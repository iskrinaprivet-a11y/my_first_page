# Mini Figma

Мини-редактор векторной графики: React 19 + TypeScript + Tailwind CSS 4 + Vite.

Учебный проект

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # tsc -b && vite build
npm run lint     # oxlint
```

## Что работает на этом шаге

- Сетка на фоне, ездящая вместе с камерой (шаг ячейки масштабируется зумом).
- Панорамирование: **зажать Пробел и тянуть мышью**.
- Зум колесом мыши от **10% до 400%**, точка под курсором остаётся на месте.
- Центрирование холста при старте, кнопки зума и сброс вида «1:1».
- Рисование прямоугольника и эллипса протяжкой мыши (R / O), горячие клавиши
  инструментов (V / R / O), Escape — отмена протяжки.
- История изменений: **Ctrl+Z** — отменить, **Ctrl+Shift+Z** (или Ctrl+Y) — вернуть.
  Отменяется результат жеста целиком: одно перетаскивание — одно нажатие, а пять
  правок цвета подряд (перетаскивание пикера) — тоже одно.
- Выделение: клик по фигуре на холсте, клик по слою в панели слоёв,
  Shift+клик — несколько фигур сразу, клик по пустому месту — снять выделение.
- Рамка выделения с восемью маркерами вокруг фигуры (4 угла + середины сторон);
  размер маркеров не зависит от зума.
- Перетаскивание выделенного мышью: на любом зуме фигура идёт ровно под
  курсором, Escape во время перетаскивания возвращает её на место.
- Вставка изображений двумя способами: **Ctrl+V** из буфера обмена и
  перетаскивание файла из проводника. Из буфера картинка встаёт в центр холста,
  из проводника — под курсором, в собственных пропорциях и с ограничением
  длинной стороны в 640 px.
- Вставленная картинка — обычная фигура: выделяется кликом, перетаскивается,
  удаляется по Delete и отменяется через Ctrl+Z. У неё нет заливки и обводки,
  поэтому в панели свойств показывается её разрешение, а не пикеры цвета.

Изменение размера маркерами и порядок слоёв — **шаг 3** (см. заготовки в
`LayersPanel.tsx`).

## Горячие клавиши

Все сочетания описаны в `src/constants/tools.ts` таблицей `HOTKEYS`: обработчик
ни о каких буквах не знает и просто спрашивает таблицу, какая команда
соответствует нажатию. Клавиши инструментов привязаны к физическим клавишам
(`event.code`), поэтому работают и на русской раскладке.

| Клавиши                        | Действие                                        |
| ------------------------------ | ----------------------------------------------- |
| `V` / `R` / `O`                | Выделение / прямоугольник / эллипс              |
| `Ctrl+V`                       | Вставить картинку из буфера обмена               |
| `Ctrl+Z`                       | Отменить последнее изменение                    |
| `Ctrl+Shift+Z`, `Ctrl+Y`       | Вернуть отменённое                              |
| `Escape`                       | Отменить жест, иначе снять выделение            |
| `Delete`, `Backspace`          | Удалить выделенное                              |
| `Пробел` + мышь / колесо       | Панорама / зум                                  |

`Ctrl+R` и `Ctrl+O` остаются системными: сочетание с `Ctrl` меняет инструмент
только там, где это описано явно. `Ctrl+V` перехватывается холстом, но только
если в буфере есть картинка — вставка обычного текста работает как обычно.

## Архитектура

Каждая папка отвечает ровно за свою часть и не знает про соседние.

| Папка             | Что внутри                                             | Зачем                                                                 |
| ----------------- | ------------------------------------------------------ | -------------------------------------------------------------------- |
| `src/types/`      | `shape.ts` — `Shape`, `ImageShape`, `Tool`, `Point`, `Rect`, `Viewport` | Единый язык проекта: TypeScript ловит несовпадения до запуска         |
| `src/constants/` | `tools.ts` — инструменты и горячие клавиши; `viewport.ts` — зум, сетка, глубина истории; `selection.ts` — рамка и маркеры; `images.ts` — правила вставки картинок | Настройки в одном месте, а не магические числа по проекту        |
| `src/utils/`      | `geometry.ts` — экранные координаты ↔ координаты канваса, хит-тест, перенос фигур; `images.ts` — файлы буфера и проводника → размер картинки | Чистая математика и работа с файлами — тестируются без React       |
| `src/hooks/`      | `useViewport`, `useShapes`, `useHotkeys`               | Логика без интерфейса: камера, данные, клавиатура — независимы        |
| `src/components/` | `Canvas`, `Shape`, `Toolbar`, `PropertiesPanel`, `LayersPanel` | Один компонент — одна зона экрана                            |

Правило зависимостей: `components → hooks → utils → constants → types`.
Обратных стрелок нет — поэтому `utils/geometry.ts` никогда не «подтянет» за собой
React.

### История изменений

`useShapes` помнит снимки состояния (фигуры + выделение) и отменяет не отдельный
вызов, а результат жеста целиком: протяжка и перетаскивание пишут в историю одну
запись при `commit`, а не по одной на каждый кадр. Соседние правки одного поля
одной фигуры (перетаскивание пикера цвета) сливаются в одну запись. Глубина
истории — `HISTORY_LIMIT` в `constants/viewport.ts`.

### Ключевая формула

Всё позиционирование держится на одном равенстве:

```
canvas = (screen - pan) / zoom
screen = canvas * zoom + pan
```

Оно живёт в `utils/geometry.ts` (`screenToCanvas` / `canvasToScreen`). Забытый
`/ zoom` — причина того, что фигуры «уезжают» относительно курсора при зуме и
сдвиге холста. Зум колеса фиксирует точку под курсором через `zoomViewportAt`.
Перетаскивание использует `screenDeltaToCanvas`: сдвиг мыши достаточно разделить
на зум, а паннорамирование из разности координат вычитается само.

### Жесты на холсте

Обе мышиные ручки из `useShapes` устроены одинаково — плоский объект с методами,
а холст о них ничего не знает:

|                     | `draw` (протяжка)              | `move` (выделение и перетаскивание) |
| ------------------- | ------------------------------ | ----------------------------------- |
| `begin`             | новый прямоугольник / эллипс   | фигура под курсором + выделение    |
| `update`            | габариты черновика             | смещение от стартовых габаритов     |
| `commit` / `cancel` | создать фигуру / отменить      | оставить на месте / вернуть назад  |

`Canvas` только передаёт события мыши: ни хит-теста, ни пересчёта координат,
ни политики выделения в нём нет. Попадание под курсором считает `hitTestShape`,
а габариты при переносе всегда собираются заново из стартовых — поэтому ошибка
сложения не копится, даже если тащить фигуру сотни кадров.
